# secret-reader の評価

## 目的

AI 検出の Agent（`secret-reader`）が、パターンでは拾えない混入（個人名・法人格の表記の無い会社名・リソース名）を、検査単位の本文から拾えるかを確かめる。あわせて、機密ではない値（予約された例示値・プレースホルダ）を報告しないこと、本文に無い値の報告が拒否されること、最終応答に値を含めないことを確かめる。

Agent は、合否も候補の区分も決めない。報告された値を区分するのは、機密判定である。ここで確かめるのは、拾う・拾わないと、報告の仕方だけである。

## 方式

1. ケース（`cases/<ID>/input.md`）を、プロジェクト内の `.temp/ai-test/<ID>/`（`.gitignore` 済み）へ複写し、複写したファイルを検査単位にして作業領域を作る
2. `secret-reader` を起動し、検査 ID だけを渡す
3. 作業領域に残った報告を読み、ケースの「期待」（`expected.md`）と比べる
4. 判定が一致しても、報告された値・位置・種別を読んで確かめる

ケースの Markdown だけがテストである。実行を補助するスクリプトは置かない（道具がテストの対象になるため）。

## 自己完結

入力に使う名前は、明らかに架空のものだけである。実在の個人名・会社名・リソース名、およびそれを一部改変したものを使わない。機密の形式（トークン・鍵・接続文字列等）に一致する値を置かない。

期待（答え）は、ケースの外の `expected.md` に置く。Agent はリポジトリを自由に読めるため、答えを `input.md` に書くと、読んだときに見つかってしまう。複写先に `input.md` だけを置き、隣に `expected.md` を置かないのも、同じ理由である。

## ケース

| ケース | 内容                                                                          | 確かめること                                                               |
| ------ | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| S01    | 個人名・法人格の表記の無い会社名・リソース名が、本文に 1 つずつある           | 3 つを拾い、種別を付けて報告する                                           |
| S02    | 予約された例示値・プレースホルダ・形だけを示す記述だけで、混入が無い          | 機密ではない値を報告しない                                                 |
| S03    | S01 の入力で、本文に無い値を `ai_add.py` に直接報告する（Agent を起動しない） | 作り話の報告が拒否され、2 回続くと `ai_finish.py` も拒否され、印が残らない |

## 実行の手順

リポジトリのルートの絶対パスを `{ルート}`、スクリプトの置き場を `{ルート}/linter/skills/secret-linter/scripts` と書く。コマンドは 1 つずつ実行する（複合コマンドにしない）。

### S01・S02: Agent の検出

1. 複写先のディレクトリを作る（`{ID}` は `S01` または `S02`）。固定のパスであり、並行して実行しない。

   ```bash
   mkdir -p "{ルート}/.temp/ai-test/{ID}"
   ```

   このパスを `{複写先}` とする。

2. ケースの入力を、`{複写先}` へ複写する。

   ```bash
   cp "{ルート}/ai_tests/cases/{ID}/input.md" "{複写先}/input.md"
   ```

3. 複写したファイルを検査単位にして、作業領域を作る。標準出力の `inspection_id` が検査 ID である。`unit_count` が 1 であることを確かめる。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/scan.py" --project-root "{ルート}" --files "{複写先}/input.md"
   ```

4. Agent ツールで `linter:secret-reader` を起動する。prompt は検査 ID だけにする（他の説明・指示・ケースの内容を添えない）。完了通知を受けるまで先へ進まない。

5. Agent の最終応答を読む。終えたことだけが述べられ、値・本文・件数・位置が含まれていないことを確かめる。

6. 終了の印を確かめる。0 で終われば、Agent は正常に終えている。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/ai_check.py" {検査ID}
   ```

7. 報告された候補を読む。作業領域の置き場は、OS の一時ディレクトリの下の `secret-linter-{検査ID}/` である。OS の一時ディレクトリは次で得る。

   ```bash
   python3 -c "import tempfile; print(tempfile.gettempdir())"
   ```

   置き場の `ai_events/` にある `NNNN.json` を、連番順に Read する。受理されたものは `result` が `accepted` で、`candidate` に `kind`・`line`・`value` がある。拒否されたものは `result` が `rejected` で、`reason` がある。

8. `expected.md` の、ケースの期待と比べる。

9. 後始末をする。作業領域を消し、複写先を削除する。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/cleanup.py" {検査ID}
   ```

   ```bash
   rm -rf "{複写先}"
   ```

### S03: 作り話の報告の拒否

Agent は起動しない。S01 の手順 1〜3 で作業領域を作ってから、次を行う。

1. 検査単位の一覧のパスを得る。標準出力の `units_path` のファイルを Read し、`unit_id` を確かめる（以下では `U0001` とする。違えば読み替える）。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/ai_units.py" {検査ID}
   ```

2. 本文に無い値を、引用符付きのヒアドキュメントで報告する。終了コードが 1 であること、標準出力の `errors` に値が含まれていないことを確かめる。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/ai_add.py" {検査ID} --unit-id U0001 --kind person_name <<'VALUE'
   存在しないはずの名前
   VALUE
   ```

3. 手順 2 をもう 1 回行う。同じく 1 で終わる。

4. 本文にある値（`テスト太郎`）を報告する。拒否が 2 回続いた後のため、本文にある値でも 1 で拒否され、何も書かれないことを確かめる。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/ai_add.py" {検査ID} --unit-id U0001 --kind person_name <<'VALUE'
   テスト太郎
   VALUE
   ```

5. 終了の印を書こうとする。1 で拒否されることを確かめる。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/ai_finish.py" {検査ID}
   ```

6. 終了の印を確かめる。1 で終わり、検査を実行できなかったことになる。

   ```bash
   python3 "{ルート}/linter/skills/secret-linter/scripts/ai_check.py" {検査ID}
   ```

7. 作業領域の `ai_events/` に、拒否の記録が 2 件だけあり、`accepted` が無いこと、`ai_done.json` が無いことを確かめる。

8. S01 の手順 9 で後始末をする。

## 結果の読み方

- 判定の一致は、内容の一致を意味しない。報告された値・位置・種別を読む
- Agent は AI で、拾う値が毎回同じとは限らない。ぶれを見るには、同じケースを繰り返す
- 実行後に、Agent の動作記録で、`ai_tests/` や `expected.md` を読んでいないかを確かめる。読んでいれば、そのケースの結果は無効である
- 報告された値は、必ず入力の本文にある（`ai_add.py` が、本文に無い値を受理しないため）。受理された値が本文にあることは、この評価の対象ではない
- S01 で、期待の 3 つのほかに値が報告されても、不具合とは限らない。報告された値が、機密と読めるか（誤検出か）を読んで判断する。誤検出は、機密判定が「要確認」に落とす設計である。ただし、S02 の期待に挙げた値の報告は、不具合として扱う
- 期待の 3 つのいずれかを拾えなかったら、見落としである。見落としは、機密の名前リストへの登録で補う設計だが、繰り返し起きるなら、定義（`secret-reader.md`）を見直す

## CI に入れない理由

判定が揺れ、実行に費用がかかるため。CI のゲート（`tests/` の単体テスト）の対象に含めず、評価は手動で実行する。Agent の定義が持つ script の呼び方・語彙・禁止の記述は、`tests/test_secret_reader_definition.py` が検証する。
