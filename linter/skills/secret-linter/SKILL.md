このスキルは機密情報の検査のみを行う。**親が依頼している他の作業（commit・PR 作成・実装等）を引き継いではならない。**

> このスキル自身を Skill ツールで再起動しない（自己再帰禁止）。

## 概要

機密情報が外部へ出る直前に検査する。commit された秘密・GitHub に書き込まれた秘密は、削除しても漏洩として扱うため、止める時点は外へ出す前である。

- **検査の範囲**: `--diff`（未 commit の変更のファイル全体）、`--branch`（push で外へ出る履歴。リモートに無い commit の追加行とコミットメッセージ）、`--files`（指定ファイル全体）、`--dirs`（指定ディレクトリ配下のファイル全体）から 1 つ指定する。複数は指定できない。省略したときは `--diff` とする
- **検出の方式**: 既知の形式と形式の手がかりに一致する値は、スクリプトが決定論的に検出する。形式を持たない混入（個人名・法人格の表記の無い会社名・リソース名等）は、`--rules-only` を付けないときだけ、カスタム Agent `linter:secret-reader` が本文を読んで検出する。`--rules-only` は速さを優先する指定で、外へ出す直前の検査などで付ける
- **判定**: 検出した値を、不合格・要確認・通過に分ける。1 件でも不合格なら全体が不合格になる。要確認は利用者に確認し、回答に従って許可リスト（プロジェクトの `.secret-linter/allowlist.yaml`）または機密の名前リスト（`~/.project-secret.yaml`）へ追記する。自動修正はしない
- **結果**: 各候補の位置・種別・値・判定を、値を元のまま利用者に示す。検査の結果はファイルに残さない。呼び出し元へ返すのは区分だけで、値を含めない

## 引数の解釈 [CRITICAL]

引数から、範囲の指定と `--rules-only` を読み取る。

| 引数            | 扱い                                            |
| --------------- | ----------------------------------------------- |
| `--diff`        | 範囲の指定。省略時もこれとする                  |
| `--branch`      | 範囲の指定                                      |
| `--files パス…` | 範囲の指定。1 つ以上のパス                      |
| `--dirs パス…`  | 範囲の指定。1 つ以上のパス                      |
| `--rules-only`  | 任意。速さを優先し、AI による検出を行わない指定 |

- 範囲の指定は 1 つだけ受理する。複数の指定が渡されたときは、検査を始めず、手順 8 へ進む（理由は「範囲の指定が複数ある」）
- 不正な値の拒否は `scan.py` の引数解析が担う。終了コード 2 を、検査を実行できなかったとして扱う
- `scan.py`・`judge.py`・`answer.py` の `--project-root` には、同じ `${CLAUDE_PROJECT_DIR}` を渡す
- `{INSPECTION_ID}` は、手順 1 の標準出力の `inspection_id` である

## 手順

終了コードは、0（完了）・1（完了しなかった。標準出力の `errors` に理由）・2（引数を受理できない）である。出力の JSON はスクリプトが返したものを読み、成否を内容から推測しない。処理の計算・分岐の判定・JSON の組み立てを、この文書の中で行わない。

### 手順 1: 検査を始める

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/scan.py" {範囲の指定} --project-root "${CLAUDE_PROJECT_DIR}"
```

- 終了コードが 0 以外: 検査を実行できなかったとして、手順 8 の最終行だけを返す。`scan.py` が自分の作業領域を消しているため、`cleanup.py` は呼ばない
- `unit_count` が 0: 手順 8 へ進む（合格）
- それ以外: `inspection_id` を以後の呼び出しへ運ぶ。`--rules-only` でないときは手順 2 へ、`--rules-only` のときは手順 4 へ進む

### 手順 2: AI による検出を依頼する

`--rules-only` でないときだけ行う。Agent ツールで、カスタム Agent `linter:secret-reader` を起動する。prompt に書くのは識別値だけである。

```
Agent ツール起動: 形式を持たない混入の検出 (subagent_type: linter:secret-reader)
prompt:
  - inspection_id: {INSPECTION_ID}
```

必読文書・検出の手順・報告の仕方は agent 定義が持つ。**prompt で指示を重ねない。**

- 最終応答（background で動いたときは完了通知）を受けるまで、手順 3 へ進まない。`ScheduleWakeup` で待たない。ターンを終えて完了通知を待つ
- Agent の最終応答から成否を読み取らない。成否は手順 3 が判定する
- Agent の起動に失敗したときは、手順 8 へ進む（検査を実行できなかった）

### 手順 3: AI による検出の終了を確かめる

手順 2 を行ったときだけ行う。

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/ai_check.py" {INSPECTION_ID}
```

- 終了コードが 0 以外: 手順 8 へ進む（検査を実行できなかった）。Agent が検出を終えられなかった場合（報告の拒否が 2 回続いたときを含む）も、ここへ収束する。これは正常な結末である
- 0: 手順 4 へ進む

### 手順 4: 判定する

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/judge.py" {INSPECTION_ID} --project-root "${CLAUDE_PROJECT_DIR}"
```

`--rules-only` が指定されているときは、同じ指定を末尾に付ける（`--rules-only` でないときは、手順 3 で確かめた AI による検出の成果を、`judge.py` が判定に含める）。

- 終了コードが 0 以外: 手順 8 へ進む（検査を実行できなかった）
- 標準出力の `confirm`（要確認の候補の一覧）が空でない: 手順 5 へ進む。全体の区分（`class`）が `fail` でも、要確認が残っていれば、先に尋ねる（要確認が残る間は、手順 7 が判定を確定できない）
- `confirm` が空: 手順 7 へ進む

### 手順 5: 要確認を利用者に尋ねる

標準出力の `confirm` の一覧（`judge.py` または `answer.py` が返したもの）の各候補について、AskUserQuestion で尋ねる。

- 種別（`kind`）と値（`value`）が同じ候補は 1 件にまとめて尋ねる。回答は、まとめた全ての候補 ID に付ける
- 1 回の質問は 4 件までである。まとめた後の件数が 4 を超えるときは、4 件ずつ尋ねる
- 質問の本文には、位置（`label`・`line`、履歴なら `commit`）・種別・値を示す。値は元のまま示す
- 回答の選択肢は、次の 3 つである。論点の提示や推奨を地の文で述べず、選択肢だけを使う

  | 選択肢                   | 回答値        |
  | ------------------------ | ------------- |
  | 機密である               | `secret`      |
  | 公開してよい（残す）     | `public-keep` |
  | 公開してよい（今回だけ） | `public-once` |

- 回答が得られなかったとき（無回答）は、手順 8 へ進む（検査を実行できなかった。理由は「要確認の確認に回答が無い」）。このとき手順 8 で `cleanup.py` を通る

### 手順 6: 回答を記録する

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/answer.py" {INSPECTION_ID} --project-root "${CLAUDE_PROJECT_DIR}" --answer {候補ID}={回答値} [--answer ...]
```

- `--answer` は、まとめた全ての候補 ID に 1 つずつ付ける。`--project-root` は、手順 1 の `scan.py` に渡したものと同じ値である
- 終了コードが 0 以外: 手順 8 へ進む（検査を実行できなかった）
- 0 で、標準出力の `confirm`（要確認の候補の一覧）が空でない: 手順 5 へ戻る
- 0 で、`confirm` が空: 手順 7 へ進む

### 手順 7: 結果を示す

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/report.py" {INSPECTION_ID}
```

- 終了コードが 0 以外（判定が確定していない等）: 手順 8 へ進む（検査を実行できなかった）
- 0: 標準出力の `body` を、そのまま利用者に示す。要約・加工・省略をしない。`class`（`合格` または `不合格`）を、手順 8 の区分として使う

### 手順 8: 後始末と最終行 [MANDATORY]

`inspection_id` がある場合は、失敗した経路でもここを通り、次を実行する。

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/cleanup.py" {INSPECTION_ID}
```

利用者向けの本文（結果）を示した後、応答の最後の 1 行として、次の 3 つのいずれかを 1 行だけ返す。最終行は呼び出し元が機械的に読むため、これ以外の文字を同じ行に足さない。

- `secret-linter: 合格`
- `secret-linter: 不合格`
- `secret-linter: 検査を実行できなかった（理由）`

理由には、スクリプトが返した `errors` の要約のうち、値・本文を含まないものだけを書く。

## 制約と禁止事項

- 検出した値は、利用者へ示す本文にだけ現れる。呼び出し元へ返す最終行・ログ・ファイルに残さない
- 結果をファイルに残さない（作業領域は `cleanup.py` が消す）
- 自動修正をしない
- commit・PR 作成・実装を引き継がない
