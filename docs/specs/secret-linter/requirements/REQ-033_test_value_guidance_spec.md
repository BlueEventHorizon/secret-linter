# REQ-033 テスト・例示の値の扱い 要件定義書

## 概要

secret-linter を使うプロジェクトの利用者と、そのプロジェクトで文書・テストを書く AI が、検査に掛からない形でテスト・例示の値を書けるようにする。人名・会社名・リソース名の予約語を定め、予約語への置き換えの助言と書き方の規律を、新設の SKILL が伝える。

## 前提条件

- プロジェクトに plugin `linter` が導入されている
- 検査の判定は REQ-032 が定める。本書は検査の仕様を変えない。予約語の定義と、置き換えの助言、規律の伝達は、新設の SKILL の動作である

## 要件一覧

### FNC-001 予約語の定義

人名・会社名・リソース名について、テスト・例示に使ってよい予約語を次のとおり定める。一覧は閉じており、完全一致のものだけが予約語である。

| 区分       | 予約語                                          |
| ---------- | ----------------------------------------------- |
| 人名       | `テスト太郎`、`テスト花子`、`Test Taro`         |
| 会社名     | `テスト商事`、`ほげ商事`、`Example Corp`        |
| リソース名 | `example-bucket`、`example-queue`、`example-db` |

### FNC-002 予約語の通過

予約語は、ファイルの場所に関わらず、検査で要確認・不合格にならない。判定は値と区分だけで決まり、置かれた場所に依存しない。

### FNC-003 置き換えの助言

新設の SKILL は、テスト用ディレクトリ内の機密に見える値を検出し、「テスト・例示の値なら ◯◯ に置き換えると通過する」旨を案内する。検出だけを行い、合格・不合格は判定しない。◯◯ は、値の区分に対応する予約語である。

- 助言の対象は、テスト用ディレクトリ内の値だけである。本番の文書に予約語（例: `ほげ商事`）が書かれることはないため、それ以外の場所では助言しない
- 実在の認証情報・秘密鍵など、値そのものが機密である場合は、置き換えではなく、失効・再発行の案内を示す
- 値を自動で書き換えない。置き換えは利用者または AI が行う

### FNC-004 テスト用ディレクトリの特定

新設の SKILL を使うたびに、AI がプロジェクトの構造からテスト用ディレクトリを見つけ、利用者に確認する。結果は残さない。ディレクトリ名の固定の一覧を持たない。

### FNC-005 規律を伝える SKILL

テスト・例示の値の書き方を伝える SKILL を新設する。

- 検査の SKILL とは別の SKILL とする
- 書き方の規律と、書き方の相談への回答を、同じ SKILL が担う
- FNC-001 の予約語と、区分ごとの対応表を載せる
- 検出を目的とするテスト（わざと検出させるテスト）を書くときの扱いも伝える

## 成功の定義

plugin `linter` を導入したプロジェクトで、AI がテスト・例示のために書く値が、要確認・不合格にならずに検査を通る。ただし、検出されることを目的とするテストは除く。
