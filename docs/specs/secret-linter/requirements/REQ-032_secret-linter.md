# REQ-032 secret-linter（機密情報の検査）要件定義書

## 概要

機密情報が Git・GitHub など外部へ出る直前に検査し、合格 / 不合格を返す。commit された秘密・GitHub に書き込まれた秘密は削除しても漏洩として扱うため、止める時点は外部へ出す前である。開発者の手元で値が見えることは流出ではなく、検査の結果は位置と値をそのまま示す。

本機能は、linter プラグインの SKILL `secret-linter`（`/linter:secret-linter`）として提供する。

何を機密とするか・許容される書き方・機密判定の区分の条件・2 つのリストの意味は、linter プラグイン内蔵の[規範文書][sensitive-spec]が定める（本書はその規範を運ぶ機能の要件を定める）。

## 用語

| 用語               | 意味                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| 機密候補           | 機密の疑いがあるとして検出された値。パターンによる検出・AI による検出のどちらも、これを生成する |
| 機密判定           | 機密候補を 2 つのリスト（FNC-3004）と突き合わせ、不合格・要確認・通過に分ける決定論的処理       |
| パターンによる検出 | スクリプトが、既知の形式や形式の手がかりに一致する機密候補を機械的に検出すること                |
| AI による検出      | サブエージェントが本文を読み、パターンでは拾えない機密候補を生成すること                        |

## 前提条件

- linter プラグインが導入されていること
- 本機能は、他のプラグインの部品（共有スクリプト・他スキルの部品）に依存せず、自己完結する
- 検査対象が git リポジトリの中にあること（`--files` で渡す外部の一時ファイルを除く）

## 要件一覧

### FNC-3001: 対象の指定

利用者・呼び出し元は、検査する範囲を次のいずれか 1 つで指定する。指定の語彙は forge プラグインのレビュー（`/forge:review`）と同じである。ただし `--branch` の範囲は、外へ出る分を検査する目的に合わせてレビューと異なる（base ブランチを取らない）。

| 指定       | 範囲                                                                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `--diff`   | 未 commit の変更のファイル全体（ステージ済み・未ステージ・未追跡の新規ファイルを含む。削除されたファイルは対象外。`.gitignore` を尊重） |
| `--branch` | push で外へ出る履歴（リモートに無い commit で追加された行と、その commit のメッセージ）                                                 |
| `--files`  | 指定ファイル全体。外部へ書き込む本文の一時ファイル（リポジトリ外のパス）を含む                                                          |
| `--dirs`   | 指定ディレクトリ配下のファイル全体（`.gitignore` を尊重）。リポジトリ全体は `--dirs .`                                                  |

- ファイルの一部だけを検査することはしない。ファイルを検査するときは全体を検査する（`--branch` の追加行を除く）
- `--branch` は作業ツリーの現状ではなく**履歴**を検査する。途中の commit で入れて後で消した秘密も push で外へ出るため
- `--branch` の範囲を base との分岐にしないのは、保護ブランチ上からの push や、base 側にある未 push の commit を取りこぼすためである。未 commit の変更は push で外へ出ないため含めない。リモートを持たないリポジトリでは全履歴が対象になる
- 複数の指定を同時に受け付けない
- 対象が 0 件（削除だけの commit、リモートに無い commit が無い等）は合格とする。エラーにしない

### FNC-3002: パターンによる検出と、利用者が起動する AI による検出

- パターンによる検出は、スクリプトによる決定論的な処理で行うことを必須とする。AI に代えない。すべての指定で常に行う
- 呼び出し元が速さを優先するときは、パターンによる検出だけの指定（`--rules-only`）を付けて起動できる。この指定では、AI による検出を行わない
- パターンは既知の形式に加え、形式の手がかりを持つ混入を検出する。法人格の表記を伴う会社名（`株式会社〇〇` 等）、散文中のパスワード（`パスワードは〇〇` 等）、言い換えたドメイン・IP（`〇〇 dot 〇〇` 等）、アプリのパッケージ名（`com.〇〇.〇〇` 等の逆ドメイン形式の識別子。予約ドメインを逆にした `com.example.app` と、広く公開された開発系のパッケージ（`org.apache`・`com.apple` 等）は通過とする。プロジェクトの許可リストに `com.example.partner.*` のように接頭辞を書けば、その配下も通過とする）
- AI による検出（形式を持たない混入の機密候補を生成する）は、パターンによる検出とは別の扱いとし、利用者が本機能を起動したとき（利用者の依頼で AI が起動したときを含む）に行う。`--rules-only` を付けたときは、AI による検出を行わない。起動した主体ではなく指定で切り替えるのは、起動の経路では利用者の意図と呼び出し元の意図を区別できないためである。AI による検出は、サブエージェントを起動して行い、すべての対象の指定（`--diff` / `--branch` / `--files` / `--dirs`）で行う
- パターンで検出できない混入（法人格の表記の無い会社名・個人名・リソース名）は、機密の名前リストに登録された後の検査から止まる。初めて現れたものが `--rules-only` の検査を通ることは、速さと引き換えに受け入れる
- AI による検出は機密候補を生成するだけで合否を決めない。機密候補をリストと突き合わせて判定するのは機密判定である
- AI による検出が、定められた出力形式に反した応答を返した場合は 1 回だけやり直し、再度反したら検査を実行できなかったものとする（検査できないまま合格にしない）

### FNC-3003: 機密判定と利用者への確認

機密候補を「不合格」「要確認」「通過」に判定し、1 件でも不合格があれば全体を不合格とする。区分の条件は規範文書が定める。

要確認は利用者に確認し、回答に従ってリストへ追記する。

| 回答         | 許可リストに残す     | 動作                                   |
| ------------ | -------------------- | -------------------------------------- |
| 機密である   | —                    | 機密の名前リストに追記し、不合格とする |
| 公開してよい | 残す                 | 許可リストに追記し、通す               |
| 公開してよい | 残さない（今回だけ） | 何も追記せず、この 1 回だけ通す        |

- メールアドレスは個人情報であり、文書用の予約値を除いて、許可リストにそのアドレスと完全に一致する項目があるときだけ通過とし、無ければ要確認とする。ドメインや `*.` の項目は、メールアドレスを通さない（個人のアドレスを一括で許さないため）。回答の選択肢は他の候補と同じ 3 つで、「公開してよい（残す）」はそのアドレスを許可リストへ追記する
- 自動修正はしない

### FNC-3004: 2 つのリスト

| リスト           | 置き場                                                                                                   | 追記の契機                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 許可リスト       | 同梱分（公開ドメイン・公開の開発系パッケージの接頭辞）と、プロジェクトの `.secret-linter/allowlist.yaml` | 「公開してよい（許可リストに残す）」の回答 |
| 機密の名前リスト | 利用者のホームの `~/.project-secret.yaml`                                                                | 「機密である」の回答                       |

- 両方に一致したら機密の名前リストを優先する
- 形式はどちらも YAML の文字列リストとする（ホームのファイル名の拡張子は `.yaml` に限る）
- プロジェクト許可リストは Claude Code に依存しない `.secret-linter/` に置く
- `~/.project-secret.yaml` が存在しないときは空のリストとして扱い、最初の「機密である」の回答で作成する

### FNC-3005: 確認の主体

利用者への確認とリストへの追記は本機能が行う。呼び出し元は確認を行わず、本機能が返す区分に従う。確認を呼び出し元に置かないのは、リストへの追記が本機能の処理であり、呼び出し元ごとに同じ確認を持たせないためである。

### FNC-3007: 起動と結果の返却

- 利用者・呼び出し元は、FNC-3001 の指定 1 つと、任意の `--rules-only`（FNC-3002）を付けて本機能を起動する。指定を省略したときは `--diff` とする（レビューの既定と同じ）
- 呼び出し元へは、「合格」「不合格」「検査を実行できなかった」を区別して返す。応答の最終行は、`secret-linter: 合格`・`secret-linter: 不合格`・`secret-linter: 検査を実行できなかった（理由）` のいずれか 1 行とし、値を含めない。「検査を実行できなかった」を合格として扱わせないため、不合格と区別して返す

### 表示要件

- 結果は合格 / 不合格と、各機密候補の位置（履歴なら commit も）・種別・値・判定を示す。値は元の文字列のまま、利用者に示す（会話に入ってよい）。呼び出し元が本機能から受け取る判定結果は区分（合格・不合格・検査を実行できなかった）だけで、値を含めない（FNC-3007）
- 検査の結果はファイルに残さない
- 抑制マーカー付きの件数と位置、読めずにスキップしたファイルと理由を示す（履歴のバイナリ等、走査しなかったものも含む）
- 通過した候補は、種別と値が同じものを 1 行にまとめ、件数と最初の位置を示す
- 検査の結果が不合格のとき、誤検出であれば行末の抑制マーカー（`secrets-scan: ignore`）で通せる旨を、結果の末尾に示す。マーカーを付けるのは、利用者の了承を得てからである

### エラーケース

| 条件                                                                       | 動作                                                             |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 対象の指定が不正（不在のファイル・ディレクトリ、複数の指定、語彙外の引数） | 検査を実行できなかったとして終了し、理由を示す                   |
| git の実行に失敗した                                                       | 検査を実行できなかったとして終了し、理由を示す                   |
| リストの形式が不正                                                         | 検査を実行できなかったとして終了し、行番号を示す（値は示さない） |
| 要確認の確認で、利用者が答えずに中断した                                   | 検査を実行できなかったとして終了する                             |
| AI による検出の応答が 2 回続けて出力形式に反した                           | 検査を実行できなかったとして終了する                             |

### 対象外

| 項目                                                    | 理由                       |
| ------------------------------------------------------- | -------------------------- |
| Git の pre-commit hook の提供                           | 後回しとする（利用者判断） |
| `--branch` でのマージ commit 自体の変更（競合の解消等） | 利用者判断                 |
